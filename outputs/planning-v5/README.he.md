# Golden City — אפיון תכנון מחייב

הגרסה ממשיכה את V4. תוצרי המידול והרינדור הקודמים נשמרו; לא נוצרו תמונות רינדור או גרסאות חדשות למסירה של אותם מבנים.

## השימוש בממשק

פתיחת תיק עם שם, כתובת וגוש מציגה את ״אפיון התכנון המבוקש״ ללא יצירת מודל. השאלון מחולק ליח״ד והעמדה, שימושים ועיצוב, שטחים וקומות, והיתכנות ואישור. אפשר לסמן ״לא ידוע — הצע חלופות״. הנתונים הקיימים באפיון או בתוכנית JSON מובנית מוצגים לאימות.

אפשר להמשיך בקליטת מקורות, סקירת מידע גיאוגרפי ובהכנת קרקע מאושרת בזמן מילוי האפיון. האפיון אינו מאשר הריסה. ההריסה דורשת בחירת מבנים, אישור גבול וגרסת מקור נפרדים.

ברירת המחדל היא 100 מ״ר פלדלת. קטגוריות הגרעין השיורי, מעליות, מדרגות, מסדרונות, פירים, לובי, שטחים משותפים, חדר דיירים, שירות, מסחר, ציבור וחניה נשמרות בנפרד. סכום הכולל מחושב רק כשכל הקטגוריות הוזנו וההפרדה אושרה. אין אימות ברוטו סטטוטורי. אומדן גרעין ראשוני משתנה לפי קומות, גובה ויח״ד בקומה; הספים והשטחים המוצעים הם הנחות היתכנות, אינם תקן אש/נגישות או תכנון מקצועי. מוצגים מניין קומות לפי הגדרת המשתמש וסך קומות פיזי, עם הפרדה למגורים, כניסה, שירות ומסחר.

לחלופות נדרשים מספר יח״ד קיים, מעטפת שטח, תכסית, מגבלת קומות, טופוגרפיה וקווי בניין שסומנו לבדיקה ואסמכתת מדיניות. כאשר היעד אינו ידוע, מוצעות תקרות קיבולת חשבוניות בלבד, לפני הקצאת לובי, שירות ושימושים נוספים; הן אינן יעד שהמערכת מאשרת. החלופות המספריות הן בדיקה חשבונית של שטחים, לא הוכחת התאמה צורנית או זכויות. בחירת חלופה אינה אישור; נדרשים גבהים ותוכנית העמדה בהמשך. מנוע האפיון הראשוני משתמש בפרופיל קומות וגובה אחיד; פרוגרמה אוטומטית לפרופילים שונים בכל מבנה עדיין חסרה.

לפני `place` מוצגים הקרקע הנקייה, הגבולות, הפרוגרמה, היח״ד/מכפיל, הקומות, השטחים, התוכנית, ההנחות והחוסרים. נדרשים שם מאשר/ת, סימון תיבת אישור ולחיצת אישור. האישור נקשר ב־SHA-256 לקרקע, לפרוגרמה ולתוכנית. שינוי בהם פוסל אותו. אישור אינו יוצר מבנים אוטומטית. העריכה ההיסטורית והצפייה במודלי מקור נשארו זמינות. רישום מקור ללא שינוי פיזי דרך alignment נשמר; שינוי מסה דרך אותו נתיב חסום בלי פרוגרמה. קליטת פרויקט שסומן כבינוי מוצע אינה עוקפת את השער. ברירת המחדל של import היא מקור שסופק לצפייה, לא אימות שלו.

הזהות בטופס אינה מאומתת באמצעות חשבון או חתימה דיגיטלית. מקור האישור הוא הצהרת משתמש ורישום ביקורת; אין בכך אישור סטטוטורי, מקצועי או הלכתי. אין אישור אוטומטי של הסוכן. אישורי השימוש בבדיקות הם של שחקן משתמש מדומה המסומן במפורש, ולא אישור של פרויקט אמיתי.

## מסירה שניתן להוריד

- `outputs/planning-v5/planning-questionnaire.html`: שאלון עצמאי למילוי. בדף GitHub לחצו **Download raw file**, שמרו HTML ופתחו ב־Chrome/Edge. השאלון אינו שולח מידע לרשת. ״שמירת אפיון״ מורידה JSON ללא אישור. אפשר לקלוט אותו שוב בשאלון או בממשק השירות. חישובי היתכנות, אומדן גרעין מלא ואישור מחייב דורשים את השירות הפעיל ונתוני מקור; הם אינם מאושרים בקובץ העצמאי.
- `outputs/planning-v5/site-viewer.html`: צפייה ב־3 מודלי V4 ההיסטוריים, ללא שינוי במודל או ברינדור. בקובץ העצמאי אפשר לסובב את המצלמה ולהוריד את המודל המקורי; פעולות עבודה חדשות דורשות שירות.
- `outputs/planning-v5/planning-and-status-v5.zip`: חבילת השאלון, התצוגה ההיסטורית, צילומי בדיקת הממשק ודוחות. זו אינה חבילת מודל קרקע אמיתית.

GitHub מציג את קוד HTML ולא מפעיל את היישום. נבדקו תוכן ההורדות, פענוח הקבצים ודפדפן Chromium. ניווט `file://` ישיר חסום במדיניות הדפדפן בענן, ולכן הבדיקה העצמאית טענה את אותם בתים ב־about:blank ללא בקשות רשת. פתיחה במחשב המקבלת אינה מאומתת. אין בשיחה כתובת שירות אינטראקטיבי ציבורית.

## האתר האמיתי — מצב עבודה

תיק המחקר והנתונים נשמרים ב־data ובמרחב המחקר הפרטי, ואינם מועלים למאגר הציבורי. נוספה קליטה בפועל משירות ArcGIS הציבורי של העירייה: גבולות חלקות, תכסיות מבנים, נקודות כתובת, נקודות גובה ומאפייני קווי גובה. כתובת וגוש בלבד נבדקים בנקודות כתובת רשמיות; אם אין התאמה, אין הסקת חלקה או מיקום. מקורות נשמרים עם SHA ותאריך שליפה. בזמן קריאת המקור אפשר להמשיך למלא את הפרוגרמה; אין נעילה גלובלית סביב רשת ה־GIS.

שרת הגיאומטריה העירוני נפתח בפועל והחזיר HTTP200, למרות רשימת רשת מוקדמת שלא הציגה אותו. הבדיקה הישירה היא ראיית הקישוריות; הרשימה המוקדמת אינה הוכחה לחסימה. במתחם המועמד מהמפה נמצאו גבולות עירוניים, תכסיות ותצלום אמיתי, אך גם סתירה בין הכתובת שנמסרה לבין הכתובות המרחביות שבמקור. נדרשת הכרעת המשתמשת לפני קביעת תחום התערבות. השטח העירוני המחושב שונה מנתוני המפה; השטח הרשום אינו זמין והסיבה להפרש המקורי עדיין לא אומתה.

מפת החלקות הופקה מתוך 20 אריחי תצוגת המפה הציבורית הרגילה, ללא ExportTiles או יצוא GP חסום. מנוע המפה ב־engine/municipal_map.py שומר קואורדינטות ומקור, ומסמן שיוך כתובת חסר. מופקת תמונה בלבד, לא קרקע חשופה או מודל מוצע. השכבה מתויגת 2026-05; יום טיסה ו־GSD מקור אינם מאומתים. נקודות הגובה אינן מזוהות כ־DTM חשוף והדאטום לא אומת. לכן המצב הקיים שנקלט הוא דו־ממדי בלבד; אין מודל תלת־ממדי או ניקוי אמיתי. עותק עבודה שומר בדיוק את תכסיות ההקשר; אין בכך הוכחת שימור תלת־ממד בעת הריסה.

חבילת המקורות האמיתיים כוללת מפה, GeoJSON, תמונת מקור עם worldfile ו־PRJ, דוח PDF ודוחות אימות. נבדקו GDAL/OGR, פענוח תמונות, PDF, חילוץ ZIP ופתיחה חוזרת; נבדקה גם הורדת ZIP דרך השירות והשוואת SHA. מאגר GitHub עדיין ציבורי. שינויו לפרטי, לפי אישור המשתמשת הקודם, נדחה בפועל ב־HTTP403: Resource not accessible by integration. אין העלאת נתוני GIS או צילום אמיתי למאגר הציבורי. בדיקת דפדפן השירות אינה הוכחה שהקבצים נגישים במחשב המשתמשת. מסירה פרטית דרך GitHub דורשת שינוי נראות ב־Settings על ידי בעלת המאגר.

נדרשים אימות תחום ההתערבות ושיוך לכתובות על בסיס הגבולות העירוניים שנקלטו, מדידה עדכנית/מודל מבנים מסווג עם גבהים, DTM מתחת למבנים עם דאטום גובה, תצלום והקשר מורשים, רשימת הריסה ואישור התערבות. אימות הרשויות, זכויות הנתונים וזרימת ניקוי/מידול אמיתי עדיין לא הושלמו; real clearing/placement נשארים חסומים. קליטת DWG, חילוץ אוטומטי של תוכנית העמדה מ־PDF, פוטוגרמטריה, פילוח רשת משולבת ושחזור DTM חסר אינם יכולות מוכחות.

## בדיקות ושחזור

```sh
.venv/bin/python scripts/test_report.py --output reports/v5-regression.json
PORT=8000 .venv/bin/python app.py
.venv/bin/python scripts/test_planning_browser.py --url http://127.0.0.1:8000
.venv/bin/python scripts/test_site_clear_browser.py --url http://127.0.0.1:8000
.venv/bin/python scripts/package_planning_v5.py
```

בבדיקות הדפדפן: תיק כתובת/גוש ללא גיאומטריה, חסימת API לפני אפיון, תוכנית אמיתית מבחינת קובץ JSON (סינתטית מבחינת האתר), אימות נתונים מוכרים, חבילת סקירה, תיבת אישור חובה, חלופות ללא מודל, שמירת/קליטת JSON עצמאי, מודלי V4 המקוריים, מצלמות, הורדה זהה בבייטים ושמירת גרסאות.

המסירה משתמשת במנגנון הבדיקות הקבוע: קיום/גודל/SHA, פענוח תמונות ב־Pillow וב־FFmpeg, פתיחת HTML ומקורותיו, בדיקת GLB במופע Blender נפרד, CRC ומניפסט מלא של ZIP, חילוץ ופתיחה חוזרת של כל החברים ושל המודלים המוטמעים. קבלת הקישור במחשב המשתמשת נשארת `not_verified` עד לאישור שלה.
